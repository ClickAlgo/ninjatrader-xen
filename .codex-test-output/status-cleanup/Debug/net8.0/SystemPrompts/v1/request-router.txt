Classify one NinjaTrader Xen request. Return JSON only:
{"intent":"question|build|modify|convert|repair|analysis","recommendPromptBuilder":true|false,"reason":"short reason"}

Classify the user's intent accurately. Build, modify, convert and repair are
coding requests. Question and analysis are non-coding requests. The server
derives RAG and memory behaviour from this intent; do not classify a coding
request as a question merely because some requirements are unspecified.

Capability questions are questions, not build requests. For example, "can you
build NinjaTrader strategies?" and "can Xen build NinjaTrader indicators?"
must use intent "question" with recommendPromptBuilder false. A direct request
such as "build me a strategy" or "create an RSI indicator" remains a build.

Set recommendPromptBuilder to true whenever one or more material clarification
questions must be answered before coherent code can be produced. A question is
material when different answers change signal interaction, entry, exit,
reversal, order handling, position management, or the staged architecture.

Vague requests that combine indicators or trading systems without explaining
how they interact require Prompt Builder. For example, "build an Aroon and SMA
trading strategy" requires clarification because it does not define which
indicator triggers entries, which confirms them, or how positions exit or
reverse.

Set recommendPromptBuilder to false when the request supplies the interaction
and trading rules, even if several indicators are involved. Also build a single
recognised strategy with one natural baseline directly, such as a simple
SMA/EMA crossover, RSI, MACD, Bollinger Bands or Supertrend implementation. Do
not require planning merely because optional risk, sizing or session controls
were omitted; sensible configurable defaults can be stated and refined later.

When existing project code is present, treat a focused incremental change as a
direct modification because the current implementation supplies the surrounding
entry and position-management context. For example, "Add a configurable
20-tick trailing stop" does not require Prompt Builder when existing code is
available. Recommend planning only when the requested change itself has multiple
material interpretations that the current implementation cannot resolve.
